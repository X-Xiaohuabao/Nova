# /next - 下一步建议

作为项目开发顾问，综合分析项目全貌后，推荐**一个最优下一步**和备选方向。

---

## 第一步：收集项目全貌（数据源，并行执行）

### 1.1 Git 提交分析（过滤非开发提交）

```bash
# 获取最近 10 条提交，包含 author/committer/message 信息
git log -10 --format="%H|%an|%cn|%s" --no-merges
```

**过滤规则**（以下提交不作为"最近在做什么"的判断依据）：

| 过滤条件 | 识别方式 | 分类 |
|---------|---------|------|
| 文档/配置提交 | commit message 以 `docs:` `chore:` `style:` 开头 | 非功能提交 |
| CI/构建提交 | commit message 以 `ci:` `build:` 开头 | 非功能提交 |

**输出**：
- 开发提交列表（过滤后的真正开发活动）
- 最近开发方向判断（根据提交涉及的模块归类：pty / profile / cost / storage / 终端 UI / 设置...）

### 1.2 活跃任务文档（最重要的数据源）

```bash
# 扫描活跃任务
ls doc/tasks/active/
```

对每个活跃任务文档，**必须深度读取**：
- 未勾选任务 `[ ]` 及其验收标准
- 最后更新时间（判断是否停滞）

### 1.3 项目状态与待办

```bash
cat doc/项目状态.md 2>/dev/null
cat doc/待办清单.md 2>/dev/null
```

提取：当前阶段、当前重点、高优先级未完成项。

### 1.4 路线图

读取 `doc/nova-roadmap.md`，提取当前阶段目标与下一里程碑。

## 第二步：分析与推荐

综合以上数据源，输出：

### 🎯 推荐的下一步（仅一个）

给出**具体可执行**的建议，格式：
- **做什么**：一句话任务描述
- **为什么现在做**：结合台账/路线图/最近提交的理由
- **怎么做**：建议入口（如「走 `/kickoff`」「继续台账 xx.md 的第 3 条」）
- **预计规模**：一轮 `/dev-loop` 可完成 / 需拆解

### 📋 备选方向（2-3 个）

每个一句话说明价值与理由，标注优先级（高/中/低）。

### ⚠️ 风险提示

发现的问题（如台账长期停滞、未勾任务与实际代码不符、架构红线隐患）。

## 约束

- **只读操作**：本命令不修改任何文件
- **不瞎编**：所有结论必须引用具体数据源（文件路径/提交 hash）
- 台账与代码状态矛盾时，以代码实际状态为准并指出矛盾
