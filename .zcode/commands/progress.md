# /progress - 项目进度报告

作为项目进度分析助手，综合分析项目全貌后，输出**结构化的全面进度报告**。

> **与 /next 的区别**：/progress 是全面的只读报告（当前状态的快照），/next 是精简的下一步建议。

---

## 第一步：收集项目全貌（数据源，并行执行）

### 1.1 Git 提交统计

```bash
# 最近 20 条提交
git log -20 --format="%H|%an|%cn|%s" --no-merges
```

**过滤规则**（不计入开发活动统计）：
- `docs:` / `chore:` / `style:` / `ci:` / `build:` 开头的非功能提交
- 合并提交（--no-merges 已排除）

**输出**：开发提交数量、按模块分布（pty / profile / cost / storage / session / ssh / 终端 UI / 设置 / 其他）、最近开发方向。

### 1.2 任务台账

```bash
ls doc/tasks/active/
```

对每个台账统计：
- 总任务数、已完成 `[x]`、未完成 `[ ]`、完成率
- 最近勾选时间（判断活跃度）
- 停滞任务（超过 7 天未动的未勾项）单独列出

### 1.3 项目状态与待办

```bash
cat doc/项目状态.md 2>/dev/null
cat doc/待办清单.md 2>/dev/null
```

### 1.4 路线图对照

读取 `doc/teacoder-roadmap.md`，对照当前完成情况标注里程碑状态。

### 1.5 代码规模参考（可选）

```bash
git ls-files "src/*.tsx" "src/*.ts" | wc -l
git ls-files "src-tauri/src/*.rs" | wc -l
```

## 第二步：输出结构化报告

```
## 📊 TeaCoder 进度报告（YYYY-MM-DD）

### 总体状态
- 项目阶段 / 整体评估 / 当前重点（1-2 句）

### 活跃特性进度
| 特性（台账文件） | 进度 | 最近活动 | 状态 |
|---|---|---|---|
| xxx | 3/7 (43%) | 2 天前 | 正常推进 |

### 近期开发活动
- 按模块归类的提交摘要（最近 1-2 周为主）

### ⚠️ 风险与阻塞
- 停滞任务、台账与代码不符、架构隐患等

### 里程碑对照
- 路线图当前阶段的达成情况
```

## 约束

- **只读操作**：不修改任何文件
- **不瞎编**：所有数字必须来自实际扫描结果，标注数据截止点
- `doc/项目状态.md` 严重过时时，提示用户走 `/update-status` 刷新
