# /dev-loop - 自主循环开发（TeaCoder，一轮一最小提交）

配合 ZCode 内置循环能力：自主连续开发，直到任务台账做完。本命令是「一轮的标准作业」。

🔴 **核心原则：本命令是「编排器」，不重复造轮子。** 实现细节走 `/dev` 的流程与技能、验收走 `/check`、进度汇总走 `/update-status`。

## 用法

- **自主连续**：每轮一个最小可提交单元，自动续期，直到台账全勾完才停。
- **手动单步**：只跑一轮（调试 / 单步推进用）。

## 参数（可选 · 圈定范围）

不带参数 = 全量按台账顺序。带一个范围参数只做一部分：
- `dev-loop profile` —— 只做 profile 相关未勾任务
- `dev-loop M2` —— 只做某里程碑
- `dev-loop <编号或关键词>` —— 单步：只做匹配那一条

规则：有参数 → 每轮只在台账里筛选匹配该范围的未勾 `[ ]`；做完即停。无参数 → 全量。

## 真相源（每轮开工必读，不可凭记忆）

1. `AGENTS.md` / `CLAUDE.md`（架构约束与编码规范，红线不可破）
2. **`doc/requirements.md`** —— 需求（只读输入，不改）
3. **`doc/teacoder-roadmap.md`** —— 路线图（判断优先级）
4. **任务台账** —— `doc/tasks/active/*.md`（`[ ]/[x]` 进度，task-tracker 格式）

## 前置门（缺则不进循环）

- **需求 / 台账都找不到** → 不瞎编，停下提示：「先走 `/kickoff` 或准备好需求 + 任务清单，再 `dev-loop`」。
- **工作区不干净**（有未提交改动）→ 先让用户确认如何处理，不混合提交。

## 一轮的标准作业

1. **读台账**：从 `doc/tasks/active/` 取第一条未勾 `[ ]` 任务（或匹配范围的那条），重读其验收标准。
2. **圈定最小单元**：本轮只做这一条；若发现它实际是 2 个以上提交的量，先拆分台账再干活。
3. **激活技能**：按影响面逐个激活对应技能（tauri-ipc / rust-coding / react-frontend / storage-sqlite / ...）。
4. **实现**：走 `/dev` 的「Rust 先行 → TS 封装 → UI → 即时验证」顺序。
5. **自检**：`cargo clippy` + `cargo test` + `pnpm exec tsc --noEmit` 全绿才算完成。
6. **提交**：`<类型>: <中文描述>`，一个任务一个提交，不混入无关改动。
7. **勾台账**：把 `[ ]` 改 `[x]`，附一行「做了什么 + 提交 hash」；若产生新待办，追加到台账末尾（`[ ]`）。
8. **收尾**：勾完最后一条时，执行 `/update-status` 汇总，并提示用户可以把 `doc/tasks/active/<特性>.md` 归档。

## 反模式（禁止）

- ❌ 凭记忆干活，不重读台账
- ❌ 一轮塞多个任务 / 一个提交混多个特性
- ❌ 跳过自检直接提交
- ❌ 修改需求文档（需求变更应停下找用户，走 `/kickoff` 补门）
- ❌ 违反架构红线（PTY 直通、Keychain、127.0.0.1）
