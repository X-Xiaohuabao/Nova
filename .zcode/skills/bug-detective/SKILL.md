# Bug 排查规范

## 排查流程（先定位，再修复）

1. **复现**：拿到确切复现步骤；不能复现的偶现问题先看日志
2. **读真相源**：报错堆栈 + `git log -5`（最近是否改过相关代码）+ 相关模块代码
3. **二分定位**：前端问题先分「IPC 数据对不对 / 渲染对不对」；后端问题先分「输入/逻辑/输出」
4. **最小修复**：只修根因，不顺手重构；修复附带防回归（测试或断言）

## Nova 常见问题速查

| 症状 | 优先检查 |
|------|---------|
| 终端闪烁 | xterm 实例是否重复创建 / DOM 未复用 |
| 中文乱码 | 编码 UTF-8 / Windows ConPTY |
| 输出丢失 | pty:output 监听卸载后未重挂 |
| CLI 检测失败 | Windows 路径/环境变量（参考 commit 026fe72 的修复） |
| 费用不显示 | CLI 本地数据文件路径 + JSONL 容错解析 |
| Profile 切换后串数据 | CLAUDE_CONFIG_DIR 是否彻底隔离 |
| 编译报非法字符 \\ufeff | BOM 问题：去 BOM + 批量扫描同目录文件 |

## 修复纪律

- 🔴 禁止"改到看起来对"——必须理解根因
- 修复后跑 `cargo clippy` + `cargo test` + `pnpm exec tsc --noEmit`
- 同类问题批量扫描（如 BOM、unwrap），一次清干净
- 结论沉淀：非显而易见的根因写进提交信息
