# 写计划规范

## 产出位置

- 特性级计划 → 台账 `doc/tasks/active/<特性名>.md`（task-tracker 格式）
- 里程碑级计划 → `doc/nova-roadmap.md` 对照更新
- 一次性探索 → 直接在对话中输出，不落文件

## 拆解原则

1. **一轮一提交**：每个任务是一个最小可提交单元，一轮 `/dev-loop` 能做完
2. **依赖显式化**：有先后依赖的任务标注「依赖: 任务N」
3. **验收可量化**：每个任务带验收标准（命令能跑通/界面可见/性能指标）
4. **影响面标注**：每个任务标注涉及模块（src-tauri 领域 / src 前端目录）

## 拆解顺序（Nova 惯例）

1. 数据层先行：SQLite 迁移 / 类型定义
2. Rust 后端：领域逻辑 + IPC 命令
3. TS 封装：invoke 层 + types
4. UI 组件 + store
5. 自检与收尾：clippy/tsc/test、文档更新

## 检查清单

- [ ] 每个任务 ≤ 一轮工作量（超过则继续拆）
- [ ] 无"等等再说"的模糊任务
- [ ] 验收标准可执行（有具体命令或指标）
- [ ] 架构红线在计划中不被触碰
