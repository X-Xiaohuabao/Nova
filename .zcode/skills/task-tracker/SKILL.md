# 任务台账规范

## 目录结构

```
doc/tasks/
├── active/    # 活跃台账（进行中的特性，一特性一文件）
└── done/      # 已归档台账（全部勾完并验收的）
```

## 台账文件格式

```markdown
# {特性名称}

- 来源: {/kickoff 或用户指定}
- 创建: {YYYY-MM-DD}
- 状态: {进行中/已完成/停滞}

## 任务清单

- [ ] 任务1（动词开头短语，一轮 /dev-loop 一个）
  - 验收: {可量化检查项}
  - 涉及: {模块/文件}
- [x] 任务2（完成于 {YYYY-MM-DD}，提交 {短hash}，做了什么一行）
```

## 使用规则

- **真相源原则**：每轮开工必读台账，**禁止**凭记忆判断进度
- 每完成一个任务立即勾选 `[x]` 并附「做了什么 + 提交 hash」一行
- 干活中发现新待办 → 追加到台账末尾（`[ ]`），不打断当前轮
- 需求变更 → 停下找用户，更新台账并记录原因，**禁止**悄悄改方向
- 全部勾完 → 走 `/update-status` 汇总 → 用户确认后移入 `doc/tasks/done/`

## 恢复上下文

新会话继续任务时：
1. 读 `doc/tasks/active/` 全部台账的未勾项与最后更新时间
2. 结合 `git log -5` 确认实际代码状态
3. 向用户确认「从哪条继续」再动手
